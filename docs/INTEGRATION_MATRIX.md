## 1. Master Subsystem Integration Matrix

| Subsystem | Existing Implementation | Identified Limitation | Research Reference | Action | Technical Scope & Reason |
|---|---|---|---|---|---|
| **Fund Tracking & Provenance** | 5-stage DAG pipeline in `flow_tracer.py` (L1 Escrow → AMM Swap → Bridge → L2 Off-Ramp → Vendor). | Static 5-hop path; lacks multi-source mixed fund proportional taint accounting and dynamic graph query engine. | **CryptoChain Explorer** | **ADAPT & EXTEND** | Implement proportional/haircut taint accounting ($ProvenanceRatio = Attributable / Total$); modularize into `ChainAdapter`, `BridgeAdapter`, `DEXAdapter`, and `OffRampAdapter`. |
| **NGO Escrow & Purpose Binding** | `PurposeBoundEscrow.sol` with 4-milestone 20/30/30/20 tranche drip and immutable category string earmark. | Monolithic contract combining escrow funds with nullifier storage; lacks pluggable external verifier modules. | **FundTrace** & **AidFlow** | **IMPROVE & EXTEND** | Preserve existing smart contract state machine; add pluggable ZK verifier interface (`IZKVerifier`), quotation hashes, and milestone claim proofs. |
| **Receipt De-duplication** | Canonical Semantic Nullifiers (`keccak256(TaxID \| InvNo \| Date \| Amount)`) + 64-bit DCT `pHash`. | Lacks secret salt blinding domain separator (`BHL_EXPENDITURE_NULLIFIER_V1`) and formal allocation isolation. | **Semaphore** & **Zerocash** | **IMPROVE & EXTEND** | Add cryptographic domain separator and private blinding salt so nullifiers cannot be brute-forced while remaining 100% deterministic across donor pools. |
| **Pixel Forgery Forensics** | Error Level Analysis (Pillow + NumPy) with Base64 heatmap and 99.2 percentile compression score. | Evaluates image pixel differences only; does not cross-correlate with bank settlement or vendor attestations. | **FundTrace** & **CryptoChain Explorer** | **EXTEND** | Combine ELA compression anomaly detection with external payment correlation (Bank UTR / NEFT reference checks). Uncorroborated receipts are flagged `UNSUPPORTED_EXPENDITURE`. |
| **Beneficiary Privacy & ZK Shield** | 142 synthetic beneficiary records with salted hashes committed to binary Merkle Tree in `flow_tracer.py`. | Merkle inclusion proof proves membership but does not constrain amount or category inside a zero-knowledge circuit. | **Aztec / Noir** & **Zerocash** | **EXTEND** | Introduce ZK expenditure verifier circuit logic proving: $H(invoice) = commitment$, $category \in authorized$, $amount \le max$, and valid nullifier derivation with 0 bytes PII leaked. |
| **Off-Chain Document Storage** | Synthetic IPFS CID manifest (`ipfs://bafybeig...`) displayed in UI and audit logs. | Document metadata can vary across formats; lacks semantic document canonicalization (whitespace, date, amount normalization). | **Levitate** & **W3C VC** | **ADD** | Implement dual-tier hashing: Raw Document Hash (`SHA-256`) + Semantic Canonical Evidence Hash (`JSON-LD` canonicalization). Store proof commitments on-chain and redacted files off-chain. |
| **Multi-Chain Ingestion & Workers** | `web3_verifier.py` querying Base Sepolia and Sepolia RPCs synchronously with simulated fallback. | Single synchronous query flow; lacks background catchup, Bloom filter event indexing, and rescan workers. | **Fystack Multichain Indexer** | **ADAPT** | Implement modular worker architecture: `RealTimeWorker`, `CatchupWorker`, `ManualWorker`, and `RescanWorker`. Expose normalized `FundFlowEvent` stream. |
| **Charity Intelligence & Verification** | Hardcoded NGO profile and verified vendor tax IDs in `campaign-seed.json`. | No live connection to independent charity registries or corporate tax records; vulnerable to Sybil NGO setups. | **OpenGive** | **ADD** | Ingest normalized external datasets (IRS 990, UK Charity Commission, Indian Darpan/80G, IATI). Add fuzzy entity resolution and automated anomaly scoring. |
| **Attestations & Decentralized Identity** | Basic vendor tax ID matching (`GSTIN-27WATER9988Z`). | No cryptographic signing by independent third-party inspectors, suppliers, or off-ramp providers. | **W3C DID Core** & **Verifiable Credentials** | **ADD** | Issue and verify W3C Verifiable Credentials: `NGOVerifiedCredential`, `VendorCredential`, `OffRampCredential`, `PaymentAttestationCredential`, `DeliveryCredential`. |
| **Autonomous Watchers & Quorum** | `DecentralizedQuorumPanel.tsx` visual consensus display with simulated multi-validator agreement. | Consensus logic is client-side; lacks decoupled autonomous backend watcher processes. | **CryptoChain Explorer** & **Fystack** | **EXTEND** | Implement independent watcher services (`FundWatcher`, `ProofWatcher`, `NullifierWatcher`, `EscrowWatcher`, `DiscrepancyWatcher`, `BridgeWatcher`) that autonomously submit fraud proofs. |
| **Discrepancy & Anomaly Engine** | Slippage skimming detector in `flow_tracer.py` comparing bridge fees to Chainlink gas oracles. | Restricted to bridge slippage; lacks multi-dimensional rules across financial, category, temporal, and reporting vectors. | **OpenGive** & **FundTrace** | **EXTEND** | Build a unified 6-domain Discrepancy Engine: Cryptographic, Financial, Category, Temporal, Provenance, and Reporting. Machine-enforce freezes on cryptographic breaches; flag reviews on statistical anomalies. |
| **Adversarial Red-Team Simulator** | 3 scenarios in `red-team/page.tsx` (Valid Milestone, Crop Double Spend, 30% Forged Batch). | Small fixed sample size (10 receipts); does not compute statistical precision, recall, FPR, FNR across large batches. | **Research Benchmark** | **EXTEND** | Build a 100-expenditure Monte Carlo simulation test suite (30 forged, 10 duplicated, 5 modified duplicates, 55 legitimate). Output formal statistical confusion matrix. |
